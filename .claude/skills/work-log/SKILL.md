# 完了の記録

目的は**同じ詰まり方を二度しないこと**。記録は Work Item（`docs/work-items/WORK-<slug>.md`）にまとめる（別の作業ログは置かない）。Work Item は次のタスクで丸ごと読まれないので、**挙動を変えるのは Step 3 の昇格だけ**。

書かなくてよいもの: Work Item を作らなかった小さな作業（タイポ・設定値の変更・調査だけ）。

## Step 1: 材料を集める

`git log --oneline` と `git diff --stat` で実際に変わったものを確かめる（会話の記憶だけで書かない）。対象の Work Item が無ければ、作業の規模を見て `task-intake` で作るかを聞く。

## Step 2: Work Item を完了にする

- **Evidence**: 変えたファイル・検証したコマンドと結果・PR。画面1つ分で足りる。実況は要らない
- **詰まった点・知見**: 詰まった点と「なぜそうなったか」（「Xで失敗→Yで直した」だけだと次に再現できない）、次に同じ領域を触る人が知っていると得をすること
- **決めたこと**: レビューで見送った指摘を「観点・ファイル・理由」で1行ずつ
- **受け入れ条件**: 満たしたものを `[x]` にする。満たしていないものは残し、`done` にしない
- **design_impact**: 設計を変えたなら `changed` と、承認済みのADRを `adrs:` に（未承認なら承認を頼む）。変えていないなら `none` と `design_impact_reason`
- `status: done` と `updated_at` を更新し、`python3 scripts/check_records.py` を通す（未チェックの受け入れ条件や未決の design_impact があれば止まる）

## Step 3: 効く知見を昇格させる（本体）

「詰まった点・知見」を1つずつ、**事実か傾向か**で分ける。迷ったら「同じ状況の他人も踏むか」で切る。

- **事実**（このプロジェクトはこうなっている）→ **1回目で昇格**
- **傾向**（自分がよく忘れる・よく指摘される）→ **2回目で昇格**。過去にあったかは**読まずに検索**する:

```bash
python3 scripts/new_doc.py grep "スコープ外|範囲外"   # 表現のぶれは | で並べる
```

0件なら今回が1回目。当たったファイルだけ開いて同じ傾向か確かめる。

| 知見 | 昇格 | 反映先 |
| --- | --- | --- |
| プロジェクト固有の約束事（層・命名・起動手順・環境の癖） | 事実 / 1回目 | `CLAUDE.md` |
| 特定の作業でしか出ない手順・注意点 | 事実 / 1回目 | 該当スキル |
| 安全に関わること | 事実 / 1回目 | `AGENTS.md` + 可能なら deny（**提案して確認を得る**） |
| 設計の決定（後から覆すと影響が大きい） | 事実 / 1回目 | ADR（`new_doc.py adr`。承認は人間） |
| レビューで繰り返し受ける指摘 | 傾向 / 2回目 | CLAUDE.md「固有の約束事」（レビュー観点になる） |
| 繰り返し忘れる段取り | 傾向 / 2回目 | 該当スキル、または繰り返すならスクリプト化を提案 |

1〜2行に削れないもの、今回限りの事情は昇格させない（CLAUDE.md が薄まる）。昇格させたら Work Item 側に「→ 昇格」と添える。CLAUDE.md・スキルを変えたら `python3 scripts/context_cost.py --ref HEAD` で常時ロードの増減を確かめる。
