# AIへの指示の置き場所を層に分ける

## 背景

AGENTS.md・CLAUDE.md・全スキルの description は毎セッション読み込まれる固定費で、整理前は 5,802文字あった。理由・背景・例が命令と混ざっていたため、守るべきルールが説明に埋もれ、トークンも使っていた。2026-11-09〜10 の会話（`WORK-slim-ai-harness`）で決めた。依頼の原文はその Work Item にある。

## 決定

AIへの指示を、読まれる頻度で次の層に分ける。

- `AGENTS.md`: 全ツール共通の作業契約。命令だけを書き、安全ルールの正本はここだけに置く
- `CLAUDE.md`: ルーティング層（80行以内）。プロジェクト固有の情報と、どの文書をいつ読むかの表だけ。説明・例・理由は書かない
- スキルの description: 発動条件（口語のトリガー語）だけ
- スキル本文: 手順と判断基準だけ。場合分けの詳細は `references/` に分け、本文の表に「いつ読むか」を書く
- 理由・背景: `docs/agent-rules-rationale.md`（ルールを変えるときだけ読む）

常時ロードを変えるときは `python3 scripts/context_cost.py --ref main` で増減を測る。

## 理由

- 毎回読まれる層を命令だけにすると、固定費が減り、守るべきルールが埋もれにくい（整理後 5,479文字、スキル本文の合計は約54%減）
- 比べた案: (a) 全部を CLAUDE.md に書く → 希釈とトークンの両方で不利。(b) AGENTS.md も削って全部スキルにする → 安全ルールが発動条件次第で読まれなくなるので採らない
- 参考: 参考にした別プロジェクト の CLAUDE.md（ルーティング層・80行以内のメタルール）

## 影響

- 理由を知りたいときは `docs/agent-rules-rationale.md` を別に読む必要がある
- hook で強制したルールも AGENTS.md の指示から消さない（hook が効かないツールでは指示だけが頼り）
- description を短くしすぎると発動しなくなるので、トリガー語は削らない
