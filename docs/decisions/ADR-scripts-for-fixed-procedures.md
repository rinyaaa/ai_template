# 決まった手順はスクリプトにし、AIは要約だけを読む

## 背景

AIが毎回同じ `git` / `gh` を叩き、長い出力を読み、同じ判断を組み立てていた（点検の収集・レビュー材料の書き写し・退避・公開前の検査・計画書の作成・ワークツリーの準備・取り込みの監査・夜間実行の成果物）。依頼の原文に「AIが同じ動きするところはスクリプト化」とある。2026-11-09〜10 の会話（`WORK-slim-ai-harness`）で決めた。依頼の原文はその Work Item にある。

## 決定

- 毎回同じになる手順は `scripts/`（夜間実行は `night-run/`）のスクリプトにし、出力は数行の要約にする。AIは要約だけを読み、スキルにはコマンドと「スクリプトが判断しないこと」だけを書く
- スクリプトは標準ライブラリだけで書き、`scripts/tests/` にテストを置いて CI で走らせる
- サブエージェントへの材料はファイルに書いてパスで渡す（中身をプロンプトに書き写さない）。結果もファイルに書かせ、返事は数行にさせる

## 理由

- トークンの大半は「何を読ませるか」で決まる。スクリプトはコマンドの組み立てと長い出力の読解を省く
- 決まった手順を機械にすると、毎回の判断の揺れが無くなる
- 比べた案: スキルに手順を詳しく書く → 毎回読まれ、毎回組み立て直すので両方で不利
- 参考: 参考にした別プロジェクト の `scripts/`（check_docs・list_work_items 等）と、委譲時の「結果はファイルに、返事は数行」

## 影響

- スクリプトの保守が要る（テスト必須）。一覧は `scripts/README.md`
- 判断を要する部分までスクリプトにしない。スクリプトの出力は判断の材料で、判断そのものではない
- `python3` が無い環境では動かない
